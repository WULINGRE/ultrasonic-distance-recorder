# LCD 显示故障排查与修改说明

日期：2026-09-26  
工程：STM32 超声波测距方案 / `tem_mis_disp.uvprojx`  
目标：STM32F103C8，ST7735S，128 × 160，4 线 SPI，RGB565。

## 1. 结论与验证范围

本次检查的是用户第一次修改后的源码。已经直接修复确认的代码问题，完成 Keil 全量编译和主机回归测试，并导出 HEX 文件。未连接实体屏幕进行测量，未执行烧录，不能将编译和主机测试通过等同于实物点亮。

本次不显示的主要原因是多个故障叠加：

1. 配置了 PA5、PA7，但仍未开启 GPIOA 时钟。
2. PB14/RST 改成普通输出后，没有任何拉高或复位操作；正常复位启动时输出锁存器默认是低电平，屏幕因此一直被复位。
3. `0x3A` 后的 `0x05` 通过 `LCD_WriteCmd()` 发送，DC 为低，控制器收不到正确的 RGB565 参数。
4. PB10 背光没有开启；若模组为高电平使能，背光保持关闭。
5. 清屏设置了整个窗口，却只发送了一个像素的数据。

前两项会直接阻断屏幕通信或运行；第三项使像素格式设置失败；第四项影响可见亮度；第五项使整屏背景填充失败。它们均是源码中可以确认的问题，实际黑屏或白屏还与模组背光电路、供电和面板状态有关。

## 2. 已确认的接线

用户已确认以下型号、分辨率和接线；本次修复保留这套接线。

| LCD 信号 | STM32 引脚 | 软件配置 |
|---|---|---|
| SCK / SCL | PA5 | SPI1 SCK，复用推挽 |
| SDA / MOSI | PA7 | SPI1 MOSI，复用推挽 |
| CS | PB12 | 普通推挽，低电平选中 |
| DC / A0 | PB13 | 普通推挽，低为命令、高为数据 |
| RST / RES | PB14 | 普通推挽，低电平复位 |
| BL / LED | PB10 | 普通推挽，当前按高电平使能 |
| GND | GND | 共地 |

当前保留双线全双工 SPI。PA6 被配置为下拉输入以接收无意义的占位字节，不需要新增屏幕 MISO 接线，也不通过该引脚读取 LCD 状态。SPI 默认映射到 PA5/PA7，保留 SWD 调试接口。

## 3. 修改文件与具体内容

### 3.1 `Hardware/st7735.c`

| 修改位置 | 修改前问题 | 修改后行为 |
|---|---|---|
| `LCD_SPI_Init()` | 缺 GPIOA 时钟 | 开启 GPIOA、GPIOB、AFIO、SPI1 时钟，明确使用 SPI1 默认映射 |
| GPIO 初始状态 | 控制脚上电状态未处理 | 配置输出前预置 CS/DC/RST 为高、背光关闭 |
| SPI 结构体 | `SPI_CRCPolynomial` 未初始化 | 先调用 `SPI_StructInit()`，再覆盖本工程参数；CRC 保持关闭 |
| `SPI_SwapByte()` | 发送后仅检查 BSY，没有明确等待接收完成 | 依次等待 TXE、发送、等待 RXNE、等待 BSY 清零，再读取并清除接收数据 |
| `LCD_Init()` | 无硬件复位、背光开启；像素参数类型错误 | 增加复位及延时、正确发送命令与参数、最后开启背光 |
| 初始化参数 | 缺少明确的面板工作参数 | 增加帧率、电源、VCOM、扫描方向、显示反色及正常显示模式配置 |
| `LCD_SetAddressWindow()` | 偏移宏未使用，地址高字节固定为零 | 应用 X/Y 偏移，分别发送地址高低字节 |
| `LCD_Fill()` / `LCD_Clear()` | 整个区域只写一个像素 | 根据包含两个端点的面积循环写入，整段像素传输保持 CS 有效 |
| 字符与中文字形 | 窗口随 size 放大，但像素数不变 | 在横纵方向重复像素，支持整数放大；拒绝 size=0 或无法完整容纳的字形 |
| 字符串 | 换行检查偏早，未处理截断三字节 UTF-8 | 根据下一个字形宽度预先换行；检查高度、空指针和 UTF-8 后续字节 |

RGB565 配置已从错误的：

```c
LCD_WriteCmd(0x3A);
LCD_WriteCmd(0x05);
```

改为：

```c
LCD_WriteCmd(0x3A);
LCD_WriteData8(0x05);
```

初始化的关键顺序：GPIO/SPI 配置 → 等待 20 ms → RST 拉低 20 ms → RST 拉高后等待 120 ms → 软件复位后等待 150 ms → 退出睡眠后等待 120 ms → 工作参数及 RGB565 → 正常模式 → 清黑 → 显示开启 → 等待 100 ms → 背光开启。复位和睡眠命令时序依据 [ST7735S 数据手册](https://files.waveshare.com/upload/e/e2/ST7735S_V1.1_20111121.pdf)。

全屏填充现在写入 128 × 160 = 20,480 个像素、40,960 字节颜色数据。地址窗口命令及参数另占 11 字节，因此一次 `LCD_Clear()` 的 SPI 总发送量为 40,971 字节。

### 3.2 `Hardware/st7735.h`

增加 `<stdint.h>`，使头文件不再依赖其他头文件间接定义整数类型。增加面板配置项：

| 配置项 | 当前值 | 含义 |
|---|---|---|
| `LCD_X_OFFSET` / `LCD_Y_OFFSET` | 0 / 0 | 保留原工程偏移，现在实际用于寻址 |
| `LCD_MADCTL` | `0xC8` | 常用竖屏扫描方向和 BGR 顺序 |
| `LCD_INVERT_COLORS` | 0 | 使用 `0x20`，关闭显示颜色反转 |
| `LCD_BL_ACTIVE_HIGH` | 1 | PB10 高电平使能背光 |

相同 ST7735 系列控制器可能搭配不同面板。当前使用常见 128×160 模组工作参数，并参考了 [Adafruit ST7735 驱动的面板初始化配置](https://github.com/adafruit/Adafruit-ST7735-Library/blob/master/Adafruit_ST7735.cpp)。这些参数并不代表已经识别了实物面板的具体版本；如屏幕供应商提供了初始化表，应以该模组资料为准。

### 3.3 `main.c`

原先 `A` 位于像素坐标 `(1,1)`，数字串位于 `(2,1)`，两者重叠。现在改为不同位置，并增加可观察的显示测试：

1. 红、绿、蓝、白全屏依次显示，各保持 300 ms（另加传输时间）。
2. 最后保持蓝底，显示红色 `A`、绿色 `1234567890`、白色 `ST7735 OK`。
3. 下方显示三个色块，四周绘制一像素白色边框。
4. 右下角小方块每 500 ms 在黄色与蓝色之间切换。

`ST7735 OK` 是固定测试文字，不是读取芯片状态得到的检测结论。闪烁方块用于观察持续刷新；初始化本身也需要约一秒，刚上电时短暂黑屏属于预期过程。

## 5. 烧录后的验收与继续定位

1. 在 Keil 中执行 Rebuild，确认没有错误，下载新生成的程序并复位运行。
2. 观察红、绿、蓝、白启动画面是否覆盖整屏，再检查最终文字和右下角闪烁方块。
3. 四条白色边框应完整可见。如果仅边缘缺失或图像小幅平移，再根据模组手册核对 X/Y 偏移；偏移错误通常不解释整个屏幕毫无变化。
4. 如果红蓝互换，核对 MADCTL 的 RGB/BGR 位；如果整体颜色呈反相，核对 `LCD_INVERT_COLORS`。不要在通信仍未工作时随意切换这些参数。

如果仍全黑或全白，按以下顺序实测：

| 检查点 | 本次程序应有的表现 | 异常时的定位方向 |
|---|---|---|
| 程序运行位置 | 能进入 `main()`、返回 `LCD_Init()` | 检查下载对象、BOOT0、复位、启动和系统时钟 |
| 屏幕电源与 GND | 满足具体模组供电要求并共地 | 电源、导线、排针接触 |
| PB14 / 屏幕 RST | 启动有低脉冲，之后保持高 | 引脚接错、短路、外部电路持续拉低 |
| PB10 / 背光 | 初始化结束后保持高 | 背光极性或驱动电路；若 BL 为裸 LED 供电端，需按模组要求提供驱动，不能仅凭 GPIO 高电平认定背光有足够电流 |
| PA5 / SCK | 发送时出现时钟；正常 72 MHz 系统下约 1.125 MHz | GPIOA 时钟、引脚配置、接线、程序是否卡住 |
| PA7 / MOSI | 与 SCK 配合的数据流 | MOSI 接错或断路 |
| PB12 / CS | 数据传输时低，空闲高 | 片选接错或电平异常 |
| PB13 / DC | 命令低、参数和像素高 | DC/CS 混接、DC 未连接 |

逻辑分析仪按 SPI Mode 0、MSB first、8 位解码。初始化应观察到 `01`、`11` 等命令，以及 **DC=0 的 `3A`，紧随 DC=1 的 `05`**。持续运行后每约 500 ms 还会出现刷新小方块的数据，可用于抓取波形。

SPI 状态标志只说明 STM32 外设完成移位，不能证明 LCD 已接收或执行命令。本程序没有屏幕 ID/状态读回。如果卡在 `SPI_SwapByte()` 的等待循环，应先查看 SPI1 的 CR1/SR 和外设时钟。

系统时钟仍使用原工程的 8 MHz 外部晶振 ×9 配置；`Delay.c` 按 72 MHz 实现。如果实际晶振不是 8 MHz，需要另行校核。若外部晶振启动失败并回退到内部时钟，当前延时会明显变长，不能将更长的启动等待误判为立即死机。晶振和实际供电未在本次远程排查中测量。
